# D1 — Real task: "Find what fills my Downloads, list duplicates, make an Excel + PDF report, open it"

Recorded 2026-11-11 on the owner's PC with the **installed** XtraOS (commit 976a448) through
the command-line bridge (`xtraos-core.exe call`, same core and rules as MCP). Every number below
is measured unless marked **estimate**. File names are left out on purpose (personal files).

## The data
- Downloads: **3,384 files, 148.1 GB**.
- Duplicates: **18 groups, 2.7 GB** that could be freed (byte-for-byte identical; 2,123 files
  compared).
- Output: `Documents\XtraOS demo\Downloads cleanup report.xlsx` (124 cells, 11 KB) and `.pdf`
  (36 KB), opened in Excel. Nothing was deleted (deleting would ask the user).

| # | Call | Time | Agent → tool | Tool → agent |
|---|---|---|---|---|
| 1 | `files.largest` (Downloads, top 10) | 0.08 s | 80 ch | 1,477 ch |

Tokens are characters ÷ 4 (an approximation; paths and numbers tokenize a little worse).
Not included: the model's own reasoning tokens and the one-time tool list in the context
(~3,400 tokens with `XTRAOS_TOOLS=core`, ~8,500 with all tools; ADR 0044), and the model's
thinking time between calls.

What the actual run also contained (honest): a `status` call (0.05 s), a read-back check
(`office.excel_read`, **24.3 s** right after writing — the file was in a OneDrive folder that
was syncing; 2.7 s when repeated), and **one wrong call**: `files.open`, which shows a file
selected in Explorer rather than opening it; the agent then used `launch_app`. Total for all
10 calls: 47.8 s, 3,588 ch out, 8,029 ch in (≈ 2,900 tokens).

## Compared with other ways (estimates — none of these were run)

| Way | Steps | Tool tokens | Time | Can it find true duplicates? |
|---|---|---|---|---|
| **XtraOS (measured)** | 6 calls | ≈ 2,000 | 19–42 s of tool time | Yes: size, then content |
| By hand: Explorer sort, eyeball duplicates, type Excel, export | ~40 clicks/keystroke runs | — | **estimate** 25–40 min | Not reliably: names differ, contents can't be compared by eye |
| Screenshot-based computer-use agent | **estimate** 30–60 GUI steps | **estimate** 50k–120k (≈ 1,400–2,200 tokens per screenshot; XtraOS measured 2,225 for a full window) | **estimate** 5–15 min | No, not from the GUI alone; it would need a terminal |
| Shell coding agent writing its own PowerShell | **estimate** 4–8 calls incl. fixes | **estimate** 3k–8k (script + output) | similar tool time if it groups by size first; much slower if it hashes all 148 GB | Yes, if the script is right |

The honest reading:
- Against **manual work** and **screenshot agents**, XtraOS is far faster and cheaper here, and
  it gets duplicates right where they cannot.
- Against a **capable shell agent** (Claude Code, Codex), the gain on this task is **moderate**:
  fewer tokens (compact pre-summarised results, no script writing and debugging), Office done
  through one call in a hidden instance with macros off, and safety a script does not give
  (protected places refused, never overwrites, deleting asks the user, kill switch, a
  tamper-evident action log).
- **Chat-only MCP clients** (Claude Desktop, Cursor chat) have no shell: without XtraOS they
  cannot do this task at all.

## Problems this run found
1. **Fixed (ADR 0069):** `files.open` read like "open the file" but showed it in Explorer → the
   agent made a wrong call. Now its description says so first, and `app: true` opens a document
   in its default app (programs and scripts refused) — the "open it" step becomes 1 call, 2.1 s.
2. **Fixed (ADR 0069):** `office.excel_write` wrote values only (dates `########`, plain
   headers). Now columns autofit (≤ 60 wide) by default and `bold` ranges style the headers;
   checked live on this report.
3. Office on a file in a syncing OneDrive folder was slow once (24 s).
4. The first duplicate scan of 148 GB took 25.7 s (it is bounded and reports `complete`).
5. The duplicate list includes copies of DLLs inside an app folder that must not be deleted; the
   report flags them, but it needs judgement (deleting asks the user anyway).
